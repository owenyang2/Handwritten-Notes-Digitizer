## 1. Complete the live app, website, and sync journey

- [ ] Create a notebook offline, draw, add/reorder/rename pages, force-quit, and
  reopen. Check every stroke and page is retained.
- [ ] Sign in and sync that notebook. Open the website and verify the same page
  order, source image, and annotations.
- [ ] Sign into a second independent native installation. Check it restores the
  same notebooks, pages, and exact saved ink.
- [ ] Import a multipage PDF and images through the actual client interfaces.
  Check page order and retained originals; annotate and export them.
- [ ] Convert mixed prose/formula pages and a whole notebook. Check region
  selection, source alignment, reading order, and retained figures.
- [ ] Exercise correction, split/merge, reorder, exclusion, and retry in the live
  review interface. Save, then reopen on another client.
- [ ] Open Markdown, LaTeX, and HTML exports and compare them with the saved
  corrections. Verify original-ink and original-source exports separately.

**Complete when:** a new drawing/import survives reopening, appears on the
website and second native client, and its saved corrections match its exports.

## 2. Verify recovery, login, and account separation

- [ ] In the browser, complete registration, sign-out/sign-in, and session reopening.
- [ ] Disconnect while editing, reconnect, and retry. Check no notes or pending edits disappear.
- [ ] Close the app during an upload, then reopen and resume it.
- [ ] Restart the backend during conversion. Check the job recovers or provides
  a clear retry, and existing documents/reviews survive the restart.
- [ ] Expire a login session and sign in again. Check local notes survive.
- [ ] Edit the same notebook on two clients. Check conflicts preserve pending
  ink and provide a usable recovery path.
- [ ] Through the live clients, check missing models, corrupt/oversized files,
  incomplete predictions, timeouts, and rate limits show useful recovery messages.
- [ ] Using a second test account, verify it cannot access another account's
  notes, ink, sources, recognition results, reviews, or exports.
- [ ] Verify data export and account deletion using disposable test accounts.

## 3. Install and test on a physical iPad

Follow the [physical iPad setup instructions](docs/MODEL_AND_IPAD_SETUP.md#your-physical-ipad).

- [ ] Connect/unlock the iPad, trust the Mac, and enable Developer Mode if requested.
- [ ] Configure signing for the app and share extension, including their shared App Group.
- [ ] Build and install the app on the connected iPad.
- [ ] Put the iPad and Mac on the same network, configure the Mac's backend
  address in the app, and pass the connection test.
- [ ] Test Apple Pencil writing, palm rejection, finger drawing/pan/zoom, and erasing.
- [ ] Check rotation, multitasking, VoiceOver, and session restoration after relaunch.
- [ ] Import through Files, Photos, and the share extension; annotate and export.
- [ ] Repeat the drawing → sync → recognition → correction → export journey on hardware.

## 4. Measure and improve handwriting accuracy

The demo establishes working inference. Its prose prediction `indus the` needs
correction; the printed formula sample does not establish handwriting accuracy.

- [ ] Correct the inaccurate prose demo transcription against its source.
- [ ] Assemble real clean/messy handwriting, formulas, mixed pages, rotated
  photos, diagrams, and blank/unreadable examples with verified answers.
- [ ] Keep final test documents separate from training/development examples.
  Record the dataset and model versions.
- [ ] Agree accuracy, critical-symbol, speed, and memory targets before evaluation.
- [ ] Measure prose character/word errors and formula correctness/structure
  errors. Include missed regions, unreadable inputs, and incomplete outputs.
- [ ] Check page coverage, reading order, export correctness, recognition speed,
  and memory use across the sample set.
- [ ] Fix failures that miss the agreed targets, rerun the relevant checks, and
  retain predictions and the quality report.

## 5. Optional: personalization and alternative models

These are additional capabilities, rather than requirements for the installed
formula/prose conversion.

- [ ] If enabling legacy prose personalization, obtain or train a verified
  compatible CRNN model and its metadata. Installed TrOCR does not enable this workflow.
- [ ] Collect consented corrections, meet the configured training threshold,
  and compare personalization with the unchanged base model on separate real test sets.
- [ ] Verify account isolation, failed-model rejection/rollback, consent withdrawal,
  and personalization reset/deletion. Do not use synthetic results as quality evidence.
- [ ] If choosing the compact formula model, train/install and evaluate a real
  compatible checkpoint. UniMERNet is already available for formula testing.

See the [model setup and training guide](docs/MATH_NOTES_SETUP_GUIDE.md).
